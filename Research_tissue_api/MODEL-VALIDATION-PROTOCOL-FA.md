# پروتکل انتخاب و اعتبارسنجی مدل تحلیل بافت زخم — WoundAI v30.4

## ۱. هدف و وضعیت
این سند چارچوب تصمیم‌گیری پژوهشی است. در v30.4 هیچ مدل واقعی انتخاب یا نصب نشده و TiSage صرفاً نامزد بررسی است. هیچ نتیجه عملکردی برای WoundAI ادعا نمی‌شود.

## ۲. دروازه‌های پیش از انتخاب
برای هر نامزد مدل، این موارد باید مستند شوند:
1. مقاله، مخزن کد، نسخه دقیق commit و Model Card.
2. فایل‌های وزن، منشأ، checksum و روش دریافت.
3. مجوز مستقل کد، وزن و داده آموزشی؛ مجوز داده لزوماً مجوز وزن یا استفاده تجاری نیست.
4. نوع زخم، محل بدن، جمعیت، رنگ/تون پوست، دستگاه تصویربرداری، محیط ثبت و تعداد بیماران در داده آموزش/آزمون.
5. روش annotation، تعداد annotatorها، توافق بین ارزیابان و روش حل اختلاف.
6. وابستگی‌ها، سخت‌افزار، زمان inference، مصرف حافظه و امکان نگهداری امن.
7. محدودیت‌های منتشرشده و مواردی که مدل برای آن‌ها طراحی نشده است.

اگر مجوز، منشأ وزن یا دامنه داده روشن نیست، مدل وارد استقرار نمی‌شود.

## ۳. طراحی مجموعه داده
- رضایت و مبنای قانونی استفاده از تصویر باید روشن باشد.
- تصاویر باید de-identify شوند و شناسه بیمار از فایل تحلیلی جدا نگهداری شود.
- تقسیم train/validation/test در سطح بیمار انجام شود؛ تصاویر یک بیمار نباید بین مجموعه‌ها نشت کنند.
- مجموعه آزمون خارجی از مرکز/دستگاه/جمعیت مستقل تهیه شود.
- توزیع نوع زخم، محل، رنگ/تون پوست، کیفیت عکس، نور، زاویه و دستگاه گزارش شود.
- annotation توسط متخصصان واجد صلاحیت و با پروتکل نسخه‌دار انجام شود.
- موارد مبهم، تصاویر کم‌کیفیت و اختلاف ارزیابان جداگانه برچسب بخورند.

## ۴. ارزیابی فنی
برای هر کلاس و هر گروه مرتبط، حداقل موارد زیر گزارش شوند:
- Dice و IoU با فاصله اطمینان.
- حساسیت و ارزش اخباری مثبت/precision.
- خطای مرز/سطح در صورت تناسب با کاربرد.
- عملکرد در تصاویر خارج از توزیع و موارد کم‌کیفیت.
- ماتریس خطا و فراوانی کلاس‌ها.
- پایداری در دستگاه‌ها، نورها، محل‌ها و گروه‌های مختلف.
- زمان inference، خطاهای runtime و نرخ خروجی نامعتبر.
- کالیبراسیون confidence در صورت تفسیر آن به‌عنوان احتمال؛ در غیر این صورت فقط امتیاز خام نامیده شود.

عدد پذیرش نباید پس از مشاهده نتیجه انتخاب شود. معیارهای پذیرش باید پیش‌ثبت و توسط کمیته فنی/بالینی تعیین شوند.

## ۵. ارزیابی بالینی و گردش‌کار
- مقایسه خروجی با annotation مرجع و قضاوت متخصصان.
- مطالعه خطاهای خطرناک: جاافتادن نکروز، اشتباه‌گرفتن بافت‌ها، مرز نادرست و ماسک نامعتبر.
- ارزیابی اثر نمایش AI بر تصمیم درمانگر و خطر اتکای بیش‌ازحد.
- ثبت اصلاح/رد ماسک توسط متخصص و نسخه مدل در audit trail.
- عدم استفاده برای تشخیص عفونت از عکس، تجویز، تعیین فوریت یا پیش‌بینی قطعی ترمیم.
- پروتکل توقف، گزارش رخداد و rollback مدل تعریف شود.

## ۶. دروازه‌های فعال‌سازی
| دروازه | شرط |
|---|---|
| G0 — انتخاب | منشأ، مجوز، دامنه و Model Card بررسی شده |
| G1 — فنی | checkpoint file موجود، SHA-256 تطبیق‌یافته و inference reproducible |
| G2 — داده | جداسازی بیمار، کیفیت annotation و آزمون خارجی آماده |
| G3 — عملکرد | معیارهای از پیش تعیین‌شده و تحلیل زیرگروه‌ها پاس شده |
| G4 — بالینی | بازبینی مستقل و تأیید کمیته بالینی/مسئول مقررات |
| G5 — استقرار | امنیت، احراز هویت، محدودیت نرخ، پایش، audit و rollback برقرار |

تا عبور مستند از دروازه‌های مربوط، خروجی پژوهشی باقی می‌ماند و `clinical_use=false` حفظ می‌شود.

## ۷. وضعیت TiSage
TiSage در این نسخه فقط candidate است. قبل از انتخاب باید دامنه داده آموزشی، سازگاری با انواع زخم هدف WoundAI، مجوز کد/وزن/داده و عملکرد در جمعیت مستقل بررسی شود. وجود مخزن یا checkpoint عمومی به معنی تناسب بالینی یا مجوز استفاده تجاری نیست.
