# WoundAI Pro — نسخه توسعه‌ای یکپارچه (Release v17)

سامانه وب واکنش‌گرا برای مستندسازی زخم، پرونده بیمار، تصویربرداری، اندازه‌گیری دستی، ارزیابی ساختاریافته، پشتیبان تصمیم مراقبتی و گزارش‌گیری.

> **وضعیت مهم:** این مخزن یک نمونه توسعه‌ای/پژوهشی است و برای استفاده عملیاتی بالینی یا نگهداری اطلاعات قابل‌شناسایی بیمار تأیید نشده است. هیچ خروجی سامانه جایگزین معاینه، تشخیص یا تصمیم درمانگر نیست.

## قابلیت‌های موجود در رابط
1. هسته برنامه و ناوبری چندصفحه‌ای
2. ثبت، ویرایش و مشاهده پرونده بیمار؛ چند زخم برای هر بیمار
3. دوربین/گالری، انتخاب ناحیه بدن، ثبت عکس و اتصال به زخم
4. کالیبراسیون مقیاس، ترسیم چندضلعی دستی، اصلاح نقاط و محاسبه مساحت در صورت کالیبراسیون
5. ماژول ANN پژوهشی برای داده‌های ساختاریافته و CSV برچسب‌خورده
6. فرم ارزیابی بالینی، شاخص‌ها و دسته‌بندی‌های ورودی ارزیاب
7. تولید پیش‌نویس برنامه مراقبتی و گردش کار بازبینی/تأیید متخصص
8. گزارش تصویری، چاپ/ذخیره PDF و تاریخچه ارزیابی‌ها
9. شناسه محلی و پشتیبان رمزنگاری‌شده قابل انتقال
10. آزمون‌های ایستای برنامه و PWA آفلاین/قابل نصب

## شروع سریع
- فایل‌های **داخل این پوشه** را در ریشه مخزن GitHub قرار دهید؛ خود ZIP را به‌عنوان فایل برنامه بارگذاری نکنید.
- در GitHub: `Settings → Pages` و منبع انتشار را روی `Deploy from a branch`، شاخه `main` و پوشه `/ (root)` قرار دهید.
- پس از انتشار، سایت را فقط با HTTPS باز کنید تا دوربین و Service Worker مجاز باشند.
- اجرای محلی اختیاری: یک وب‌سرور استاتیک اجرا کنید؛ بازکردن مستقیم `index.html` با `file://` برای دوربین/PWA مناسب نیست.

## ارتقای تجربه کاربری در نسخه ۱۳
- رابط گزارش‌گیری با کارت‌های تصویری و تفکیک روشن‌تر اطلاعات بازطراحی شده است.
- بخش مقایسه طولی، دو تصویر آخر ثبت‌شده برای همان زخم را کنار هم نمایش می‌دهد.
- تاریخ مراجعه و مساحت ثبت‌شده زیر هر تصویر درج می‌شود.
- تغییر نسبی مساحت در صورت وجود دو اندازه‌گیری معتبر محاسبه می‌شود.
- کاربر می‌تواند برگه مقایسه دو مراجعه را به PNG ذخیره کند.
- مقایسه تصویری به حداقل دو تصویر نیاز دارد؛ برای مقایسه دقیق باید زاویه، فاصله، نور و مقیاس ثابت باشند.

## آزمون‌های توسعه
نیازمند Node.js 20 یا بالاتر:
```bash
node --check app.js
node --check sw.js
node tests/smoke-check.mjs
```
GitHub Actions همین آزمون‌ها را روی push و pull request اجرا می‌کند.

- لوگوی افقی جدید در سربرگ کناری و گزارش PNG؛ لوگوی مربعی برای آیکون صفحه اصلی/لمسی.
- به‌روزرسانی رنگ نوار وضعیت مرورگر، پس‌زمینه نصب PWA و کش فایل‌ها.
- حفظ کنتراست و تفکیک رنگ وضعیت‌ها؛ رنگ مرجانی برای هشدار/نمایش بافت و سبز برای تأکید مثبت.

## گزارش حرفه‌ای و روند مراجعات در نسخه ۱۶
- گزارش PDF تاریخچه اکنون یک صفحه خلاصه، نمودار روند مساحت، جدول مقایسه بافت/ترشح/عفونت و صفحه جداگانه هر مراجعه دارد.
- در صفحه هر مراجعه، اطلاعات عروقی، نوروپاتی، کاهش فشار، مداخلات و یادداشت درمانگر نمایش داده می‌شود.
- پیش‌نمایش گزارش، تعداد مراجعات و خلاصه تغییر مساحت را نشان می‌دهد.
- تصویر هر مراجعه تا حد امکان با شناسه تصویر متصل به همان ارزیابی انتخاب می‌شود تا عکس آخر به‌اشتباه به مراجعات قدیمی نسبت داده نشود.
- خروجی PNG گزارش فعلی نیز نمودار روند مساحت را در صورت وجود حداقل دو اندازه‌گیری معتبر نمایش می‌دهد.

## پیشنهادهای بالینی مبتنی بر راهنما در نسخه ۱۵
- پیشنهادهای مشروط بر اساس اتیولوژی و داده‌های واردشده توسط درمانگر تولید می‌شوند.
- ورودی‌های تکمیلی شامل ABI، TBI، نبض پا، نوروپاتی، محل کف‌پایی، offloading، خطر فشاری، تحرک و تغذیه است.
- پیشنهادهای دیابتی با IWGDF/IDSA و IWGDF، آسیب فشاری با راهنمای بین‌المللی ۲۰۲۶ و عفونت با IWII ۲۰۲۶ هم‌راستا شده‌اند.
- برای زخم وریدی، تا پیش از ثبت داده پرفیوژن، برنامه فشرده‌سازی پیشنهاد نمی‌شود.
- منبع هر دسته پیشنهاد در خروجی برنامه مراقبتی قابل مشاهده است؛ فهرست و دامنه منابع در `clinical-guidelines/` ثبت شده است.
- سامانه آنتی‌بیوتیک، دوز دارو، فشار فشرده‌سازی یا روش دبریدمان تجویز نمی‌کند.

## پردازش تصویر کمکی در نسخه ۱۴
- ابزار رشد ناحیه رنگی با انتخاب seed و حساسیت قابل تنظیم، فقط برای پیشنهاد مرز است.
- مساحت از شمارش پیکسل‌های ماسک و مقیاس ثبت‌شده محاسبه می‌شود؛ روش و پارامترها در رکورد ذخیره می‌شوند.
- ترسیم دستی بسته‌شده بر ابزار کمکی اولویت دارد.
- جدول روند مراجعات، درصدهای بافت، نوع ترشح و شدت عفونتِ ثبت‌شده توسط ارزیاب را کنار مساحت نشان می‌دهد؛ این مقادیر از تصویر استنتاج نمی‌شوند.
- این روش CNN آموزش‌دیده، تشخیص بافت یا تشخیص عفونت نیست و باید توسط درمانگر بازبینی شود.

## وضعیت هوش مصنوعی
- ANN فعلی روی داده‌های ساختاریافته و CSV برچسب‌خورده کار می‌کند و صرفاً پژوهشی است.
- هیچ مدل آموزش‌دیده و اعتبارسنجی‌شده برای تشخیص/قطعه‌بندی تصویر زخم در این بسته وجود ندارد.
- پیش‌بینی ANN را نباید برای تشخیص، اولویت‌بندی اورژانسی، تجویز دارو یا انتخاب درمان استفاده کرد.
- برای توسعه معتبر لازم است داده ناشناس‌شده و دارای مجوز، تعریف دقیق پیامد، تقسیم داده در سطح بیمار، آزمون مستقل، اعتبارسنجی خارجی، تحلیل زیرگروه‌ها و تأیید کمیته اخلاق/متخصص فراهم شود.

## ذخیره‌سازی و امنیت
- نسخه GitHub Pages فعلی داده‌ها را در LocalStorage همان مرورگر نگه می‌دارد؛ این پایگاه داده امن یا چنددستگاهی نیست.
- پشتیبان رمزنگاری‌شده AES-GCM فقط از فایل خروجی محافظت می‌کند؛ داده فعال داخل مرورگر رمزنگاری سمت سرور یا مدیریت دسترسی واقعی ندارد.
- برای توسعه بک‌اند، migration و راهنمای پایه Supabase در `supabase/` و `backend/README-FA.md` آمده است. **این بک‌اند هنوز به رابط متصل نشده است.** راه‌اندازی آن به پروژه و کلیدهای واقعی، تنظیمات منطقه میزبانی، تست RLS و بازبینی امنیتی نیاز دارد.
- هرگز کلید `service_role`، رمز دیتابیس یا اسرار را در کد فرانت‌اند یا مخزن عمومی قرار ندهید.
- تا پیش از تکمیل احراز هویت، کنترل نقش، رمزنگاری، ثبت رخداد، پشتیبان‌گیری سروری، بررسی قانونی و آزمون نفوذ، اطلاعات واقعی بیمار وارد نکنید.

## فایل‌ها
- `index.html`, `styles.css`, `app.js`: رابط و منطق سمت مرورگر
- `sw.js`, `manifest.webmanifest`, `assets/`: PWA
- `tests/smoke-check.mjs`: آزمون ایستای اصلی
- `.github/workflows/validate.yml`: CI
- `supabase/migrations/`: طرح اولیه پایگاه داده چندمرکزی و RLS
- `backend/README-FA.md`: راه‌اندازی و محدودیت اتصال بک‌اند
- `گزارش-آزمون-و-نقشه-راه-نسخه-۱۲.md`: گزارش ممیزی و موارد باقیمانده
