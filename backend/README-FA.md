# زیرساخت ابری WoundAI — وضعیت v30.2

این پوشه راهنمای زیرساخت ابری است. نسخه ۳۰.۲ اتصال بدون وابستگی ثالث به Supabase Auth و PostgREST را از طریق فایل‌های `supabase-config.js`، `supabase-client-v30.js` و `supabase-ui-v30.js` اضافه می‌کند.

## قابلیت‌های پیاده‌سازی‌شده در v30.2
- پیکربندی Project URL و کلید عمومی Publishable/Anon از صفحه امنیت.
- ردکردن کلیدهای `service_role` و `sb_secret_*` در مرورگر.
- ورود با ایمیل/گذرواژه از Supabase Auth.
- نگهداری توکن نشست در `sessionStorage`، نه `localStorage`؛ پاک‌سازی نشست هنگام خروج.
- ثبت و تأیید عامل TOTP و بررسی سطح AAL2.
- فهرست عضویت‌های مرکز و ایجاد مرکز با RPC امن.
- خواندن محدود فهرست پرونده‌های ابری برای آزمون اتصال.
- RLS چندمرکزی، نقش‌های owner/admin/clinician/reviewer/viewer و محدودیت نوشتن به نقش‌های بالینی با MFA.
- جداول `encounters` و `appointments`، کلیدهای مرکب برای جلوگیری از اتصال زخم/بیمار به مرکز دیگر، و audit trigger برای تغییرات داده.
- bucket خصوصی تصاویر و سیاست‌های Storage با بررسی امن شناسه پوشه.

## هنوز انجام نشده
- فرم‌های اصلی بیمار و زخم هنوز LocalStorage را استفاده می‌کنند.
- مهاجرت یا همگام‌سازی اطلاعات محلی به ابر انجام نمی‌شود.
- عملیات ایجاد/ویرایش پرونده از فرم اصلی به سرور متصل نشده است.
- audit مشاهده/خواندن هنوز پیاده‌سازی نشده است.
- محدودیت نرخ tissue research API و احراز هویت مستقل آن باقی است.
- اجرای migration و آزمون واقعی RLS/MFA/Storage روی پروژه Supabase انجام نشده است.
- رمزنگاری سمت برنامه، تنظیم پشتیبان‌گیری خودکار/PITR و آزمون بازیابی در پروژه میزبانی باید جداگانه انجام شوند.

## راه‌اندازی
برای مراحل کامل و آزمون tenant isolation، فایل `supabase/README-FA-v30.2.md` را بخوانید. تا زمان تکمیل آزمون‌های استقرار، از اطلاعات واقعی بیمار استفاده نکنید.
