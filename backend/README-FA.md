# راه‌اندازی بک‌اند امن WoundAI (پایه Supabase)

این پوشه یک **زیرساخت شروع و قابل بازبینی** برای احراز هویت، چندمرکزی، نقش‌ها، پرونده‌ها، ارزیابی‌ها، پلن مراقبت، ثبت رخداد و فضای خصوصی تصاویر فراهم می‌کند. این به معنی فعال‌شدن بک‌اند در نسخه استاتیک GitHub Pages نیست.

## پیش‌نیاز
1. ایجاد پروژه اختصاصی Supabase در منطقه جغرافیایی مجاز برای داده‌های سلامت.
2. بررسی قرارداد پردازش داده، محل میزبانی، GDPR و قوانین محل فعالیت.
3. اجرای migration در `supabase/migrations/202611100001_woundai_core.sql` روی محیط آزمایشی.
4. ساخت کاربر اولیه و کلینیک؛ افزودن عضویت کاربر به `clinic_members` با نقش owner از محیط امن مدیریت.
5. فعال‌کردن MFA، محدودیت ثبت‌نام، ایمیل بازیابی، سیاست رمز عبور و محدودیت نرخ درخواست.
6. آزمون RLS با دو کلینیک و چند نقش؛ تلاش برای خواندن داده کلینیک دیگر باید رد شود.
7. بررسی policyهای Storage و مسیرگذاری فایل‌ها. Bucket خصوصی است و لینک عمومی نباید ساخته شود.

## کلیدها
- کلید publishable/anon فقط در صورت نیاز کلاینت قابل استفاده است و همچنان RLS باید فعال باشد.
- هرگز `service_role`، کلید خصوصی، رمز دیتابیس یا کلید امضای JWT را در کد مرورگر، GitHub Pages یا مخزن عمومی قرار ندهید.
- فایل `.env` واقعی را commit نکنید.

## وضعیت اتصال رابط فعلی
رابط فعلی هنوز از ذخیره‌سازی محلی استفاده می‌کند. برای اتصال عملیاتی باید یک adapter سمت کلاینت/سرور نوشته و تست شود تا عملیات بیمار/زخم/عکس/ارزیابی/پلن را با user session و clinic_id به جداول متناظر منتقل کند؛ همچنین migration داده محلی، conflict handling، حذف/اصلاح، signed URL، audit و همگام‌سازی آفلاین باید طراحی شوند. تا آن زمان این SQL فقط پایه زیرساخت است و دکمه ورود ابری یا همگام‌سازی در رابط فعال نشده است.

## امنیت و مقررات
این اسکیمای شروع، ممیزی امنیتی یا تأیید انطباق نیست. داده سلامت حساس است. قبل از استفاده واقعی: DPIA، مبنای قانونی پردازش، رضایت/اطلاع‌رسانی، مدت نگهداری، حق دسترسی/اصلاح/حذف، رمزنگاری، مدیریت رخداد، پشتیبان‌گیری، آزمون نفوذ و بازبینی حقوقی/بالینی لازم است.
